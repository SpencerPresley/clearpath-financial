# Frontend

Vite + React + TypeScript (strict). TanStack Router (file-based), Query, Form, Table, Charts, Markdown.
Tailwind v4 + daisyUI for styling, React Aria Components for interactive primitives (menus, comboboxes,
popovers, dialogs).

## Layout

```
src/
  routes/       file-based routes; thin: wire a route to a feature component
  features/     one folder per product area (queue, review, submit, terms, partners, library, import, assistant)
  api/          mutator.ts (the only fetch), queryClient.ts, generated/ (orval output)
  ui/           shared, feature-agnostic components (layout, primitives)
  theme/        theme.css: the only place tokens and component classes are defined
  test/         setup, MSW server, render helpers
  routeTree.gen.ts   generated by the router plugin
```

Features import from `api/`, `ui/`, and `theme` classes, never from other features. Shared code moves to `ui/`.

## Generated code: never hand-edit

- `src/api/generated/**` comes from `openapi/ninja.json` via `npm run generate:api`. When the backend
  schema changes, re-export `openapi/ninja.json`, regenerate, and commit both.
- `src/routeTree.gen.ts` is regenerated by the router plugin on `dev`/`build`.
- Generated output: React Query hooks + models, MSW handlers (`*.msw.ts`), zod schemas (`*.zod.ts`).

## API calls

Use the generated hooks. All requests go through `src/api/mutator.ts`: same-origin session cookie, and
`X-CSRFToken` from the `csrftoken` cookie on unsafe methods. Non-2xx responses throw `ApiError`. In dev, Vite
proxies `/api` and `/_allauth` to `http://localhost:8000` (override with `VITE_DEV_BACKEND_URL`).

## Styling

- Tokens and component classes live only in `src/theme/theme.css`.
- Tailwind's default palette is reset (`--color-*: initial`): only ClearPath tokens exist (`bg-primary`,
  `text-base-content`, `border-base-300`, ...). `bg-blue-500` generates nothing.
- Prefer daisyUI semantic classes (`btn`, `badge`, `menu`, `table`) and app classes (`app-*`, defined with
  `@apply` in theme.css) over long utility strings in JSX. If a utility combination repeats, it becomes an
  `app-*` class.

## Testing

- Unit (`npm run test:run`): Vitest + jsdom + Testing Library. MSW intercepts the network with the generated
  handlers as defaults (`src/test/server.ts`); override per test with `server.use(...)`. Unhandled requests
  fail the test. Use `renderWithQuery` from `src/test/render.tsx`.
- Browser (`npm run test:browser`): `*.browser.test.tsx`, real Chromium via `@vitest/browser-playwright` and
  `vitest-browser-react`. Only for behavior jsdom can't express (layout, focus, real events).
- E2E (`npm run test:e2e`): Playwright against `vite preview` of the production build; stub the API with
  `page.route`.
- First-time setup for browser and e2e: `npx playwright install chromium`.

## Commands

| Command                | What it does                                             |
| ---------------------- | -------------------------------------------------------- |
| `npm run dev`          | Dev server on :5173                                      |
| `npm run build`        | Typecheck + production build to `dist/`                  |
| `npm run lint`         | ESLint (type-aware, incl. no-floating-promises)          |
| `npm run format`       | Prettier write                                           |
| `npm run format:check` | Prettier check (CI)                                      |
| `npm run typecheck`    | `tsc -b`                                                 |
| `npm run test`         | Unit tests, watch mode                                   |
| `npm run test:run`     | Unit tests, once (CI)                                    |
| `npm run test:browser` | Browser-mode tests                                       |
| `npm run test:e2e`     | Playwright e2e                                           |
| `npm run generate:api` | Regenerate `src/api/generated` from `openapi/ninja.json` |
